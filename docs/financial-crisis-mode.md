# 금융 위기 이벤트 모드 v1

## 수업 흐름

기본 모드는 유지한다. 신규 수업을 만들 때 AI 자동 생성을 끄고, 게임 관리 → 수업 모드 → 금융 위기 이벤트를 선택한다. 학생·가격·뉴스가 없는 설정 중 수업에서만 확정할 수 있다. 종목 2~12개, 두 종류 이상의 가상 기업 특성, 시작 가격, 난이도를 선택하면 6일 가격표와 속보를 한 트랜잭션으로 저장한다.

1. Day 1: 가상 기업 특성과 현금 비중을 살핀다.
2. Day 2: 양호한 실적과 대출 심사 강화라는 서로 다른 신호를 만난다.
3. Day 3: 자금 조달 불안을 관찰한다.
4. Day 4: 시장 전체의 하락과 기업별 차이를 경험한다.
5. Day 5: 정책 대응 이후에도 남는 불확실성을 판단한다.
6. Day 6: 거래를 마치고 당시 이유·가격 변화·해설을 돌아본다.

모든 참가자가 같은 일차·가격·속보를 사용한다. 기본 뉴스 화면에도 현재까지 공개된 가상 속보가 나타난다. 홈·분석 화면에 선택 이유와 해설을 제공하며, 이유는 실제 주문과 별개의 자기 보고 기록이다. 선택형 이유와 선택 입력 500자 메모를 저장하고, 현재 Day에서만 수정할 수 있다. 수익률 순위에 이유 점수를 섞지 않는다. 강사는 게임 관리에서 이유를 조회한다.

## 변경 경계와 데이터

- `class_market_scenarios`가 없는 수업은 기본 모드다. 기존 수업을 자동 전환하거나 기존 가격·뉴스를 교체하지 않는다.
- `0036_financial_crisis_events.sql`은 테이블 2개를 추가한다. **배포 전에 승인된 환경에서 마이그레이션을 먼저 적용해야 한다. 이번 작업에서는 운영 DB에 적용하지 않았다.**
- 서버 전용 `crisis-engine.ts`가 일차별 가격과 해설을 확정한다. 학생 응답은 현재 속보와 지난 Day의 해설만 허용 목록으로 반환한다. 기존 `getNewsByDay`의 미래 Day 조회도 차단했다.
- 모드 설정·기본 가격/뉴스 편집·Day 이동은 수업 행 잠금으로 충돌을 조정한다. 이벤트 거래/이유 기록은 수업 공유 잠금, 거래는 학생 지갑 잠금도 사용한다. 전체 학생의 거래를 하나씩 직렬화하지 않는다.
- 이벤트 거래는 서버의 확정 가격·정수 수량·현재 Day·진행 상태를 검증한다. 최종 Day 거래는 차단한다. 기존 기본 모드의 계산·거래 규칙은 그대로다.
- 이벤트 수업의 수동 Day 변경, 기간/난이도/프로그램 변경, 가격·뉴스 직접 변경을 서버에서 차단한다. Day +1에 현재 Day를 함께 보내 중복 클릭·오래된 화면의 재실행을 거부한다.
- 설정 재시도는 기존 시나리오를 반환하며 가격·뉴스를 중복 생성하지 않는다. 학생별 Day별 이유는 유일 인덱스로 보호한다. 학생/수업 삭제 시 이유도 삭제된다.
- 실제 기업 평가가 아닌 수업용 역할이다. 차입 의존형·균형형·생활 수요형과 가상 가격 경로임을 관리자·학생에게 안내한다. 쉬움은 쉬운 표현과 기준가 대비 절반 규모의 변동이다.

## 요구사항 → 검증 근거 (2026-11-27)

| 요구사항 | 구현 | 검증 |
| --- | --- | --- |
| 기본 모드 보존 | 선택 테이블, 신규 빈 수업만 설정 | 기본 가격 저장·모드 미설정·기존 데이터 전환 차단 테스트 |
| 동일한 사건과 사후 해설 | 서버 시나리오 생성·공개 범위 제한 | 결정적 가격, 쉬움 변동폭, 미래 속보·해설 비공개 테스트 |
| 이유 저장 | 학생 세션 기반 upsert, 현재 Day 검증 | 다른 학생 기록 비공개, 과거 수정 차단, 길이 제한 |
| 거래와 수업 진행 | 가격표 연결, 상태/가격/수량 검증, 수업 잠금 | 실제 PGlite DB 매수·매도·잔액, Day 불일치·최종일 차단 |
| 관리자 설정 | 기존 게임 관리에 패널·시나리오·이유 조회 추가 | 외부 수업·종목 차단, 중복 설정, 우회 편집 차단 |
| 모바일·실패 복구 | 기본 HTML 폼, 독립 스크롤 표, 상태/오류 표시 | Chrome + 모바일 WebKit 이벤트 UI 8개, 기존 UI 8개, 로딩 62개 통과 |

- 전체 서버/계산/인증 테스트 46개 통과. 테스트 DB는 PGlite이며 운영에 연결하지 않는다.
- 세 앱 타입 검사 통과. 주식 게임·재무 시뮬레이션 production build 통과.
- 관리자 production build는 컴파일·타입 검사 통과 후 기존 로컬 `NEXT_PUBLIC_STACK_PROJECT_ID` 미설정으로 page-data 수집에서 중단. 인증 설정이 있는 배포 환경의 빌드 확인이 필요하다.
- Chrome DevTools에서 학생/관리자 실제 컴포넌트 렌더링과 가로 넘침을 확인했다. 콘솔 오류·경고 없음. 캡처는 격리된 샘플 데이터다.
- 자체 diff 검토. 별도 에이전트 검토나 실제 수업 운영 검증은 하지 않았다.

초기 UI 검증에서 발견한 관리자 가격표의 모바일 넘침은 grid 자식 `min-width: 0`으로 수정했고, 재검증은 통과했다. Chromium 테스트는 설치된 Chrome 채널을 사용한다. 관리자 로컬 빌드 환경 오류는 한 번 확인했으며 임의 인증값으로 우회하지 않았다.

## 로컬 재현

```sh
pnpm test
pnpm test:browser --workers=1
pnpm test:events
pnpm test:loading
pnpm preview:events
```

미리보기: `http://localhost:14313/tests/events/index.html`. 실제 신규 UI 컴포넌트와 로컬 액션 대역을 사용한다. 운영 로그인·거래는 하지 않는다. 상단에서 Day/학생·관리자/저장 실패/읽기 실패를 선택할 수 있다. 테스트 전용 fixture에는 전체 시나리오가 있지만, 학생 production bundle에는 서버 시나리오를 포함하지 않는다.

## v1의 한계

이번 버전은 금융 위기 하나의 고정 경로다. 반복 참가 시 경로를 외울 수 있으므로 여러 위기 경로나 수업별 시드 선택은 후속 범위다. 임의 AI 가격, 실시간 시장 가격, 학생별 불리한 사건, 자동 서술형 채점은 포함하지 않는다. 사건 자체의 학습 효과는 실제 수업 피드백으로 별도 평가한다.

Modern Web Guidance `forms`의 fieldset/legend, native radio/textarea, 명시적 제출, 48px 터치 영역, 16px 입력 글꼴, 서버 검증 및 상태 알림을 적용했다.
