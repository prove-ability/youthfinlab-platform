# 금융 위기 이벤트 모드 v1

## 수업 흐름

기본 모드는 유지한다. 신규 수업을 만들 때 AI 자동 생성을 끄고, 게임 관리 → 수업 모드 → 금융 위기 이벤트를 선택한다. 학생·가격·뉴스가 없는 설정 중 수업에서만 확정할 수 있다. 이벤트 모드와 난이도를 고르면 새싹테크·든든산업·온기생활 3개, 시작 가격 각각 10,000원을 자동 구성한다. 직접 수정은 접힌 고급 설정에서 직접 구성 사용을 켜고 종목 2~12개와 특성·가격을 지정한다. 확정 시 10일 가격표와 속보를 한 트랜잭션으로 저장한다.

1. Day 1: 가상 기업 특성과 현금 비중을 살핀다.
2. Day 2: 양호한 실적과 대출 심사 강화라는 서로 다른 신호를 만난다.
3. Day 3: 자금 조달 불안을 관찰한다.
4. Day 4: 시장 전체의 하락과 기업별 차이를 경험한다.
5. Day 5: 정책 대응 이후에도 남는 불확실성을 판단한다.
6. Day 6: 정책 이후 다시 하락하는 시장을 살핀다.
7. Day 7: 기업별 대응과 수요 차이를 비교한다.
8. Day 8: 새로운 회복 신호로 판단을 점검한다.
9. Day 9: 엇갈린 전망 속에서 마지막 거래와 이유를 기록한다.
10. Day 10: 거래를 마치고 당시 이유·가격 변화·해설을 돌아본다.

새로 확정하는 이벤트는 10일이다. 기존에 저장된 6일 시나리오는 덮어쓰지 않고 원래 마지막 날에 종료한다.

모든 참가자가 같은 일차·가격·속보를 사용한다. 기본 뉴스 화면에도 현재까지 공개된 가상 속보가 나타난다. 홈·분석 화면에 선택 이유와 해설을 제공하며, 이유는 실제 주문과 별개의 자기 보고 기록이다. 선택형 이유와 선택 입력 500자 메모를 저장하고, 현재 Day에서만 수정할 수 있다. 수익률 순위에 이유 점수를 섞지 않는다. 강사는 게임 관리에서 이유를 조회한다.

## 변경 경계와 데이터

- `class_market_scenarios`가 없는 수업은 기본 모드다. 기존 수업을 자동 전환하거나 기존 가격·뉴스를 교체하지 않는다.
- `0036_financial_crisis_events.sql`은 테이블 2개를 추가한다. **배포 전에 승인된 환경에서 마이그레이션을 먼저 적용해야 한다. 이번 작업에서는 운영 DB에 적용하지 않았다.**
- 서버 전용 `crisis-engine.ts`가 일차별 가격과 해설을 확정한다. 학생 응답은 현재 속보와 지난 Day의 해설만 허용 목록으로 반환한다. 기존 `getNewsByDay`의 미래 Day 조회도 차단했다.
- 모드 설정·기본 가격/뉴스 편집·Day 이동은 수업 행 잠금으로 충돌을 조정한다. 이벤트 거래/이유 기록은 수업 공유 잠금, 거래는 학생 지갑 잠금도 사용한다. 전체 학생의 거래를 하나씩 직렬화하지 않는다.
- 이벤트 거래는 서버의 확정 가격·정수 수량·현재 Day·진행 상태를 검증한다. 최종 Day 거래는 차단한다. 기존 기본 모드의 계산·거래 규칙은 그대로다.
- 이벤트 수업의 수동 Day 변경, 기간/난이도/프로그램 변경, 가격·뉴스 직접 변경을 서버에서 차단한다. Day +1에 현재 Day를 함께 보내 중복 클릭·오래된 화면의 재실행을 거부한다.
- 설정 재시도는 기존 시나리오를 반환하며 가격·뉴스를 중복 생성하지 않는다. 학생별 Day별 이유는 유일 인덱스로 보호한다. 학생/수업 삭제 시 이유도 삭제된다.
- 실제 기업 평가가 아닌 수업용 역할이다. 차입 의존형·균형형·생활 수요형과 가상 가격 경로임을 관리자·학생에게 안내한다. 쉬움은 쉬운 표현과 기준가 대비 절반 규모의 변동이다.

## v1의 한계

이번 버전은 금융 위기 하나의 고정 경로다. 반복 참가 시 경로를 외울 수 있으므로 여러 위기 경로나 수업별 시드 선택은 후속 범위다. 임의 AI 가격, 실시간 시장 가격, 학생별 불리한 사건, 자동 서술형 채점은 포함하지 않는다. 사건 자체의 학습 효과는 실제 수업 피드백으로 별도 평가한다.

Modern Web Guidance `forms`의 fieldset/legend, native radio/textarea, 명시적 제출, 48px 터치 영역, 16px 입력 글꼴, 서버 검증 및 상태 알림을 적용했다.

## 어려움 난이도

이벤트 전용 난이도로 어려움을 추가한다. 기본 모드 초기값과 이벤트의 보통 초기값은 유지한다. 쉬움·보통의 가격 경로·속보는 변경하지 않는다. 어려움은 별도 10일 속보·가격·해설을 사용하며 상반된 정보, 기업별 반응 차이, 반등 후 재하락을 비교하도록 구성한다. 무작위로 학생별 불이익을 주지 않는다.

난이도는 시나리오 JSON에 저장한다. 기존 클래스 difficulty enum은 변경하지 않고 어려움의 기본 거래·지원금 규칙은 보통을 사용한다. 교사용 이벤트 패널에는 어려움으로 표시한다. 추가 DB 마이그레이션은 필요하지 않다. 어려움도 고정 경로이며 반복 학습에서 예측 가능성이 사라지는 것은 아니다.

미리보기: http://localhost:14313/tests/events/index.html?difficulty=hard (운영과 분리된 가상 데이터). 관리자 화면에서 새 수업 설정 체험 → 금융 위기 이벤트 → 어려움으로 직접 설정할 수도 있다.

어려움 추가 검증: 서버 테스트 49개, Chrome·모바일 WebKit UI 10개, 세 앱 타입 검사 통과. 기본 모드/보통 초기값, 실제 어려움 가격 거래, 이유 저장·다음 날 해설, 마지막 날 마감, 미래 정보 비공개를 검증했다. DevTools에서 어려움 속보·10일 선택·가로 넘침 없음을 확인했다.

## 기본 구성 자동 적용

기본값은 자동 구성이다. 확정 전 3개 기업의 이름·특성·시작 가격을 표시하고, 서버가 수업 전용 가상 종목을 생성한다. 기존 종목은 재사용하거나 수정하지 않는다. 구성 및 가격·뉴스는 동일 트랜잭션에서 저장하며 응답 유실 후 재시도도 종목을 중복 생성하지 않는다. 기본 모드를 선택한 상태에서는 이벤트 저장을 실행하지 않는다.

고급 설정을 여는 것만으로 직접 구성이 활성화되지 않는다. 직접 구성 사용 체크를 꺼야 기본 구성으로 돌아간다. 설정을 접어도 선택은 유지되며 요약에 직접 구성 사용 여부·종목 수가 표시된다. 기본 구성을 사용하는 동안 고급 입력은 disabled라 검증이나 제출을 방해하지 않는다.

검증: 서버 테스트 51개, Chrome·모바일 WebKit UI 14개, 관리자 타입 검사 통과. 자동 생성·중복 방지·권한/기존 데이터 보호·기본 구성으로 실제 거래·기본/고급 전환을 확인했다.

## 상태별 새싹 연출

기존 펠트 새싹 원본을 그대로 사용하고 SVG 구름·발표문·비교 카드·노트를 합성한다. 현재 공개된 속보 제목만으로 관찰/불안/시장 충격/정책 발표/정보 점검을 선택한다. 다음 날 가격·해설·수익률은 연출 입력으로 받지 않는다. 상승 화살표·축하·매매 신호는 표시하지 않는다.

정지 상태가 기본이며 fine pointer 데스크톱과 prefers-reduced-motion:no-preference에서만 transform/opacity 1.6초 1회 애니메이션을 적용한다. 같은 Day의 폴링·입력에는 재생을 반복하지 않으며 새 Day 또는 페이지 재진입 시 등장 연출을 한다. 모바일·움직임 줄이기 환경에서는 모든 그림이 정지한 최종 상태로 보인다.

검증: 서버 51개, Chrome·모바일 WebKit 이벤트 UI 18개, 주식 앱 타입 검사 통과. 모든 상태 전환, 1회/2초 이내 종료, reduced motion 최종 상태, 모바일 가로 넘침을 검증했다. 기존 가격 경로는 변경하지 않았다.

## 난이도에 충격 강도 통합

별도 강도 설정 없이 신규 보통/어려움 시나리오에 더 큰 변동을 반영한다. 보통 차입 의존형 Day 3→4→5는 9,800→6,500→8,200원(-33.7%, +26.2%), 어려움 Day 3→4→5→6은 9,700→5,900→7,500→5,500원(-39.2%, +27.1%, -26.7%)이다. 이는 교육용 가정이며 종목·일차별로 다르고 모든 종목의 고정 변동률이 아니다.

쉬움은 이전 원본 가격 경로를 별도로 유지해 기존 가격이 바뀌지 않는다. 기본 모드·거래 계산·애니메이션은 그대로다. 기존 저장된 시나리오 JSON은 수정하지 않으며 신규 확정부터 반영한다. 상반된 뉴스와 사후 해설은 새 경로의 방향과 일치하는지 확인했다.

검증: 서버 51개, Chrome·모바일 WebKit UI 18개, 관리자 타입 검사 통과. 실제 새 가격의 매수·매도·잔액, 쉬움 10일 가격 보존, 미래 정보 비공개 및 기존 시나리오 재시도 보존을 확인했다.

### 보통 충격 완화

추가 피드백에 따라 보통만 완화했다. 차입 의존형 Day 3→4→5→6은 9,800→7,300→8,200→7,500원(-25.5%, +12.3%, -8.5%)이다. 균형형 위기일 -16%, 생활 수요형 약 -5.9%로 기업별 차이는 유지한다. 쉬움·어려움·이미 저장된 수업은 변경하지 않는다. 위의 보통 강도 기록은 이전 시안이다. 서버 51개 및 관리자 가격표 Chrome/모바일 WebKit 2개 테스트 통과.

## 첫 수업 안내·기록 현황·개인 자산 회고

- 미설정 수업은 준비 → 학생 판단 → 다음 Day → 회고 안내를 펼쳐 보여준다. 설정된 수업에서도 다시 열 수 있다. 난이도별 사건·가격 경로가 고정된다는 설명은 접지 않고 표시한다.
- 관리자 패널에 현재 Day의 이유 기록 완료/전체/미작성 인원을 표시한다. 30초 폴링 및 수동 갱신을 제공한다. Day +1 서버 처리 시 최신 미작성 인원을 확인하고, 명시적으로 계속 진행한 경우에만 전환한다. 학생의 이유 작성 자체를 강제하지 않는다.
- 기존 판단 유지/다른 이유 선택지를 추가한다. 이유와 거래는 별도이며 점수에 포함하지 않는다.
- Day 전환 시 현금·종목 평가액·보유 비중과 다음 시세 적용 평가액을 저장한다. 지원금 10만 원과 이후 거래를 시세 변동 손익에서 제외한다. 하루 전체 매매 수익률로 표현하지 않는다. 과거 기록이 없으면 추정하지 않으며 학생은 본인 기록만 조회한다.
- 배포 전 0036에 이어 **0037_market_portfolio_reviews.sql** 적용이 필요하다. 이번 로컬 작업에서는 운영 DB 마이그레이션/배포를 실행하지 않았다.
- 검증: 격리 PGlite 서버 테스트 53개 및 Chrome/모바일 WebKit UI 22개 통과. 미작성 확인 전 무변경, 확인 후 전환·지원금 분리, 이후 거래에도 기록 보존, 재전환 중복 방지, 학생별 조회 격리, 과거 기록 없음과 추가 이유 저장을 확인했다. DevTools에서도 안내·카운트·가로 넘침 없음을 확인했다. 기본 모드와 기존 난이도 경로는 변경하지 않았다.
